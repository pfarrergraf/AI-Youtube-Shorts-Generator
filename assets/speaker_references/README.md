# Speaker reference and hero repertoire

This directory stores public reference images and approved, text-free AI hero
plates for thumbnail generation.

## Workflow

1. Use the speaker's `source/` images as identity references when creating a
   new hero.
2. Store only text-free hero plates under that speaker's `heroes/` directory.
3. Add every approved asset to `manifest.json` with its speaker, variant and
   source attribution.
4. The thumbnail renderer adds the headline with Pillow. Image models must not
   render the final headline.
5. Runtime default is repertoire-first. If no approved hero exists, use the
   real video-frame renderer; never silently invent a synthetic face.

## Providers

The heroes created during the Codex experiments were generated by the hosted
Codex image-generation tool. They did not use this workstation's GPU. The
local app cannot call Codex's internal quota directly.

Possible app providers are therefore separate and explicit:

- `repertoire`: local approved hero assets; deterministic and offline.
- `comfyui`: local workstation GPU, useful for backgrounds, matting and
  relighting; identity preservation must pass review.
- `azure_openai_api`: Azure Foundry GPT-image-2 using the project `.env` below;
  reference-image requests use the Image API and save a review candidate into
  a speaker's `jobs/` directory.

## Azure configuration

The authoritative file is `ai-youtube-shorts-generator/.env` (not the
workspace root `.env`). The generator loads it explicitly, even when the CLI
is started from another working directory. Existing generic names are
supported:

```dotenv
api_key=...
endpoint=https://.../openai/v1/images/generations
deployment_name=gpt-image-2
```

The normal thumbnail pipeline never calls Azure. Generate a new candidate only
with `tools/azure_image_hero.py`; it is written to `jobs/`, never auto-approved,
and must be reviewed before promotion to `heroes/`.

Generated assets should be reviewed before being promoted from a temporary
job directory into `heroes/`.
